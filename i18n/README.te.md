## సంస్థాపన

Linux, Python 3.12 మరియు అనుకూల Ascend టార్చ్/CANN పర్యావరణాన్ని ఉపయోగించండి. పిన్ చేయబడిన vLLM, vLLM-Ascend మరియు[పర్యావరణ గమనికలు](../docs/environment.md)లో వివరించిన vLLM-Omni స్టాక్‌లను ఇన్‌స్టాల్ చేయండి. సంబంధం లేని ఫ్రేమ్‌వర్క్ విడుదలలను కలపవద్దు. అప్పుడు మూలం నుండి ఈ రిపోజిటరీని ఇన్‌స్టాల్ చేయండి:

```bash
git clone https://github.com/Huage001/Ascend-H3.git
cd Ascend-H3
source /path/to/Ascend/cann/set_env.sh
bash scripts/install_stack.sh /path/to/private/framework-sources
export H3_ASCEND_CACHE=/path/to/writable/ascend-h3-cache
h3-ascend build --method all --soc Ascend910B3
```

బిల్డ్‌లు మోడల్ వెయిట్‌లను కలిగి ఉండవు మరియు NPUని ఆక్రమించకుండా నడుస్తాయి. స్థానిక లైబ్రరీలు స్థానికంగా సంకలనం చేయబడ్డాయి మరియు చెక్అవుట్ వెలుపల ఉంచబడతాయి. ఒకే బ్యాకెండ్ కోసం, `all`ని `vsa`, `veda` లేదా `spark`తో భర్తీ చేయండి; పూర్తి మరియు VDNకి ఈ అనుకూల CANN పొడిగింపులు అవసరం లేదు. సవరించగలిగే చెక్అవుట్‌ను అందుబాటులో ఉంచుకోండి.

## తనిఖీ కేంద్రాలు మరియు అల్గోరిథం ఎంపికలు

| పద్ధతి | అవసరమైన మోడల్ ఆస్తులు | గణన |
| --- | --- | --- |
| `full` | H3 బేస్; LightX2V డిఫాల్ట్‌గా 8-దశలు లేదా సంఘం LoRA | దట్టమైన శ్రద్ధ |
| `vsa` | మొత్తం 50 శిక్షణ పొందిన కంప్రెషన్ గేట్‌లతో సహా అధికారిక FastH3 V2 విద్యార్థిని పూర్తి చేయండి | 8 ఫార్వర్డ్‌లు, 80% వీడియో స్పార్సిటీ; లాజికల్ KV64, ఎంచుకున్న KV బ్లాక్‌లు చిప్‌లో KV128కి జత చేయబడ్డాయి |
| `veda` | H3 బేస్ + LightX2V 8-స్టెప్ + అధికారిక శిక్షణ పొందిన Veda ప్రిడిక్టర్ | డైనమిక్ పర్-హెడ్ Veda బ్లాక్ రూట్‌లు, నామమాత్రంగా 90% స్పార్సిటీ |
| `vdn` | H3 బేస్ + అధికారిక VDN స్టేజ్-DMD చెక్‌పాయింట్ డైరెక్టరీ | స్థానిక సాఫ్ట్‌మాక్స్ ప్లస్ 128-డైమెన్షనల్ లెర్న్ డెల్టానెట్ బ్రాంచ్ |
| `spark` | H3 బేస్ + LightX2V 8-దశ | Spark-H3 క్రమానుగత విభజన మరియు ఉమ్మడి ఖచ్చితమైన/ప్రాక్సీ సాఫ్ట్‌మాక్స్, నామమాత్రపు 90% ఖచ్చితమైన-బ్రాంచ్ స్పార్సిటీ |

మోడల్‌లను వాటి అసలు లైసెన్స్‌ల క్రింద డౌన్‌లోడ్ చేయండి. బరువులు పునఃపంపిణీ చేయబడవు. వేర్వేరు స్వేదన విద్యార్ధులు వేర్వేరు షెడ్యూల్‌లను కలిగి ఉంటారు మరియు నియమాలను నేర్చుకున్నారు; ఏకపక్ష బరువులపై దృష్టిని మార్చుకోవడం సరిపోలే నాణ్యతకు హామీ ఇవ్వదు. VSAకి జీరో కాని శిక్షణ పొందిన గేట్లు అవసరం. VDNకి దాని నేర్చుకున్న శాఖ బరువులు అవసరం. డౌన్‌లోడ్ మరియు ప్రిపరేషన్ ఆదేశాలు[మోడల్ ఆస్తులు](../docs/weights.md)లో ఉన్నాయి.

పూర్తి, Veda మరియు స్పార్క్ డిఫాల్ట్‌గా పిన్ చేసిన **LightX2V ఎనిమిది-దశల LoRA**ని ప్రారంభిస్తాయి. అసలైన అనేక-దశల మోడల్‌ను అమలు చేయడానికి `--no-few-step-lora`ని ఉపయోగించండి. సిద్ధం చేయబడిన సంఘం `--lora /models/style` లోడ్ అయ్యే ముందు LightX2Vతో కలిసి ఉంటుంది; మరొక సంఘం విద్యార్థిని స్పష్టంగా ఎంచుకున్నప్పుడు డిఫాల్ట్ విద్యార్థిని నిలిపివేయండి. Vedaకి ఎల్లప్పుడూ దాని అధికారిక శిక్షణ పొందిన ప్రిడిక్టర్ అవసరం. VSA పూర్తి అధికారిక **FastH3 V2 పూర్తి తనిఖీ కేంద్రం**ని మాత్రమే అంగీకరిస్తుంది: ఎనిమిది ఫార్వర్డ్‌లు, 80% వీడియో స్పార్సిటీ, వీడియో/ఆడియో షిఫ్ట్‌లు 10/3, tile64, మార్గదర్శకత్వం 1. ఇది విడుదలైన బరువులను నేరుగా లోడ్ చేస్తుంది మరియు `--lora` తీసుకోదు. VDN దాని పూర్తి అధికారిక దశ-DMD తనిఖీ కేంద్రం మాత్రమే అంగీకరిస్తుంది. అదనపు సంఘం LoRA లేదా విద్యార్థి-డిసేబుల్ ఫ్లాగ్‌ని కూడా అంగీకరించదు.

```bash
# Optional: provide the exact pinned LightX2V source locally instead of downloading.
h3-ascend serve --method full --model /models/MiniMax-H3 --devices 1 \
  --few-step-source /models/minimax_h3_fl2v_turbo_8step_v1.0_768p_bf16.safetensors
# Optional original 50-step model; the reporting baseline is Full eight-step.
h3-ascend serve --method full --model /models/MiniMax-H3 --devices 1 --no-few-step-lora
# General already-scaled Diffusers community LoRA, with no forced step schedule.
h3-ascend prepare-lora --source /models/style.safetensors --output /models/style
```

అధికారిక PEFT మూలం దాని డిక్లేర్డ్ ఆల్ఫా/ర్యాంక్ ఉపయోగించి ఒకసారి సాధారణీకరించబడుతుంది; సిద్ధం చేసిన ఫైల్‌లు హ్యాష్-చెక్ చేయబడతాయి. ఎంచుకున్న అన్ని అడాప్టర్‌లు TP స్లైసింగ్ మరియు INT8 పరిమాణానికి ముందు విలీనం అవుతాయి. అభ్యర్థన-సమయం LoRA మాతృక గుణకారాలు లేవు. సోర్స్ ఫార్మాట్‌లు మరియు స్థిర షెడ్యూల్‌ల కోసం[మోడల్ తయారీ](../docs/weights.md) చూడండి.

## సర్వర్‌ని ప్రారంభించండి

ఇతర గణన ప్రక్రియలు లేని పరికరాలను మాత్రమే ఉపయోగించండి. ఒక కార్డు కోసం:

```bash
export ASCEND_RT_VISIBLE_DEVICES=0
h3-ascend serve --method full --model /models/MiniMax-H3 \
  --precision int8 --devices 1 --offload text
```

ఇతర బ్యాకెండ్‌లు ఒకే సర్వర్ APIని ఉపయోగిస్తాయి:

```bash
h3-ascend serve --method vsa --model /models/FastH3-V2 \
  --precision int8 --devices 1 --offload text
h3-ascend serve --method veda --model /models/MiniMax-H3 \
  --predictor /models/veda/predictor.safetensors \
  --precision int8 --devices 1 --offload text
h3-ascend serve --method vdn --model /models/MiniMax-H3 \
  --lora /models/VDN/stage-dmd-step-250 --precision int8 --devices 1 --offload text
h3-ascend serve --method spark --model /models/MiniMax-H3 \
  --precision int8 --devices 1 --offload text
```

ఎంచుకున్న పరికరాలలో ఒకేసారి ఒక సర్వర్‌ని అమలు చేయండి. మోడల్‌ను లోడ్ చేయకుండా ఉత్పత్తి చేయబడిన స్థానిక vLLM-Omni ఆదేశాన్ని తనిఖీ చేయడానికి `--dry-run`ని జోడించండి.

సింగిల్-కార్డ్ ఉదాహరణలు INT8 DiT రెసిడెంట్‌ను ఉంచుతూ టెక్స్ట్ ఎన్‌కోడర్‌ను ప్రసారం చేస్తాయి. స్థానిక వంటకం DiTని పరిమాణం చేస్తుంది; టెక్స్ట్ ఎన్‌కోడర్ BF16గా మిగిలిపోయింది, కాబట్టి దాని మెమరీ ఫుట్‌ప్రింట్ ఇంకా లాంచ్ పాలసీలో చేర్చబడాలి. **BF16** కోసం, `--precision bf16`ని ఉపయోగించండి; అవసరమైతే `--offload layer --no-precompute-adaln`ని స్పష్టంగా ఎంచుకోండి. INT8 స్థానిక వంటకాన్ని ఉపయోగిస్తుంది:

```json
{"transformer":{"method":"int8"}}
```

INT8 అంచనాలు BF16 Q/K/Vని దృష్టిలో ఉంచుతాయి. అటెన్షన్ అక్యుమ్యులేటర్‌లు, Veda అంచనాలు మరియు VDN స్థితి వాటి నిర్దేశిత ఖచ్చితత్వాన్ని ఉంచుతాయి. ఇది INT8 మోడల్ అనుమితి, ప్రతి అటెన్షన్ ఆపరేషన్ INT8 అని దావా కాదు. స్థానిక వంటకం BF16లో మద్దతు లేని లేయర్‌లను కలిగి ఉంది. సింగిల్-కార్డ్ H3 96,768-వైడ్ ప్రొజెక్షన్‌ను కలిగి ఉంది, ఇది NPU పరిమాణాత్మక మాట్ముల్ అవుట్‌పుట్ పరిమితి 65,535ని మించిపోయింది; TP దాని ప్రతి-ర్యాంక్ వెడల్పును పరిధిలోకి తగ్గించగలదు.

`--devices` 1, 2, 4, 7 మరియు 8కి మద్దతు ఇస్తుంది, ఇది 56 హెడ్‌లను విభజిస్తుంది. Veda షార్డింగ్ తర్వాత గ్లోబల్ ప్రిడిక్టర్ హెడ్ IDలను కలిగి ఉంటుంది. ఏడు-కార్డ్ DiT TP ఒక టెక్స్ట్ ఎన్‌కోడర్ ర్యాంక్‌ను ఉపయోగిస్తుంది ఎందుకంటే దాని 64 ప్రశ్న / 8 KV హెడ్‌లను ఏడుతో భాగించలేరు. `--offload none` (నివాసి బరువులు)కి డిఫాల్ట్‌ని ప్రారంభిస్తుంది. మెమరీ సరిపోకపోతే, `--offload text` పరికరంలో DiTని ఉంచేటప్పుడు టెక్స్ట్ ఎన్‌కోడర్‌ను మాత్రమే ప్రసారం చేస్తుంది; `--offload module` పూర్తి భాగాలను మార్పిడి చేస్తుంది (ప్రయోగాత్మక అర్హత); `--offload layer` రెండు భాగాలను స్ట్రీమ్ చేస్తుంది, ఒక యాక్టివ్ మరియు ఒక ప్రిఫెచ్డ్ బ్లాక్‌ను ఉంచుతుంది. దిగువన పూర్తి చేసిన సరిపోలిన-ఆఫ్‌లోడ్ సూచన రెండు హార్డ్‌వేర్ ప్లాట్‌ఫారమ్‌లలో `--offload layer` (`omni-layer-prefetch1-vae-resident-v1`)ని స్పష్టంగా ఉపయోగిస్తుంది. కొత్త ఎండ్-టు-ఎండ్ కొలతలు **INT8ని మాత్రమే** ఉపయోగిస్తాయి, రెసిడెంట్ ఎగ్జిక్యూషన్‌తో ప్రారంభించి మరియు అవసరమైన ప్రతి ఆఫ్‌లోడ్ ఫాల్‌బ్యాక్‌ను గుర్తు చేస్తుంది. వివిక్త శ్రద్ధ మరియు DiT-బ్లాక్ పోలిక రెండు పరికరాలలో BF16ని ఉపయోగిస్తుంది: లేయర్‌లు 0/24/49, ఒక్కొక్కటి మూడు పరుగులు, తొమ్మిది సమయాలను సంగ్రహించి తొమ్మిదితో భాగించడం. ఐచ్ఛిక `--parallel ulysses` VDN కాని మార్గాల కోసం బహిర్గతం చేయబడింది; TP డిఫాల్ట్‌గా ఉంటుంది. స్థానిక టైల్డ్ VAE డీకోడింగ్ ఇప్పుడు ఎంచుకున్న అన్ని కార్డ్‌లకు డిఫాల్ట్‌గా ఉంటుంది (`--vae-parallel-size 0`); ఒకే డీకోడర్ ర్యాంక్ కోసం `--vae-parallel-size 1`ని ఉపయోగించండి. INT8 పూర్తి / 124-ఫ్రేమ్ పైప్‌లైన్ ఒకటి, రెండు, నాలుగు మరియు ఎనిమిది VAE ర్యాంక్‌లతో ఆమోదించబడింది. ఇతర పద్ధతి/ఫ్రేమ్-కౌంట్ కాంబినేషన్‌లు E2E మ్యాట్రిక్స్‌లో ఉంటాయి.

నివాసి NPU లాంచ్‌లు సర్వర్ సంసిద్ధతకు ముందే AdaLN ఫలితాలను సిద్ధం చేస్తాయి. తయారీ లోడ్ చేయబడిన మోడల్‌ను పరిష్కరిస్తుంది మరియు LoRA యొక్క వాస్తవ సిగ్మా స్థానాలు, DiT నవీకరణ గణన మరియు వీడియో/ఆడియో షిఫ్ట్‌లను విలీనం చేస్తుంది; ఇది ఎనిమిది దశలకు హార్డ్-కోడెడ్ కాదు. టీచర్/కస్టమ్-స్టూడెంట్ లాంచ్‌ని పేర్కొనడానికి `serve --steps N`ని ఉపయోగించండి మరియు అదే గణనను `generate --steps N`లో ఉపయోగించండి. విరుద్ధమైన స్వేదన తనిఖీ కేంద్రం షెడ్యూల్ తిరస్కరించబడింది. అవసరమైన ప్లాన్‌లతో కాష్ సామర్థ్యం పెరుగుతుంది. అసలు ప్రొజెక్షన్ గణితం అలాగే ఉంచబడింది; AdaLN మాస్టర్ బరువులు CPUలో ఉంటాయి, అయితే సిద్ధం చేసిన ఫలితాలు NPUలో ఉంటాయి. ```
