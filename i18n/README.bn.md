MiniMax H3 অনুমান Ascend-এ সম্পূর্ণ, VSA, Veda, VDN এবং Spark-H3 মনোযোগ একটি সংগ্রহস্থলে। ইন্টিগ্রেশন vLLM-Omni মডেল লোডিং, INT8 ট্রান্সফরমার কোয়ান্টাইজেশন এবং নেটিভ টেনসর প্যারালাল অ্যাটেনশন হেড পুনরায় ব্যবহার করে।

**প্রমাণিত সুযোগ:** 40/40 INT8 E2E সেল 1344×768, 124/345 ফ্রেম এবং 1/2/4/8 NPUs (37 টাটকা পরিমাপ এবং 3টি স্পষ্টভাবে চিহ্নিত ঐতিহাসিক স্তর-অফলোড সেল)। Ascend 910B3 এবং PRO 6000-এর বাসিন্দা BF16 তুলনাতে 20টি মনোযোগ-কোর এবং 20টি সম্পূর্ণ-ব্লক পরিমাপ রয়েছে। মনোযোগ অপারেটররা তাদের বৈধ সংস্করণ ধরে রাখে।

## ইনস্টলেশন

Linux, Python 3.12 এবং একটি সামঞ্জস্যপূর্ণ Ascend টর্চ/CANN পরিবেশ ব্যবহার করুন।[পরিবেশের নোট](../docs/environment.md) এ বর্ণিত পিন করা vLLM, vLLM-Ascend এবং vLLM-Omni স্ট্যাক ইনস্টল করুন। সম্পর্কহীন ফ্রেমওয়ার্ক রিলিজ একত্রিত করবেন না. তারপর উৎস থেকে এই সংগ্রহস্থল ইনস্টল করুন:

```bash
git clone https://github.com/Huage001/Ascend-H3.git
cd Ascend-H3
source /path/to/Ascend/cann/set_env.sh
bash scripts/install_stack.sh /path/to/private/framework-sources
export H3_ASCEND_CACHE=/path/to/writable/ascend-h3-cache
h3-ascend build --method all --soc Ascend910B3
```

বিল্ডগুলিতে কোনও মডেল ওজন থাকে না এবং কোনও NPU দখল না করেই চলে৷ নেটিভ লাইব্রেরিগুলি স্থানীয়ভাবে সংকলিত হয় এবং চেকআউটের বাইরে রাখা হয়। একটি একক ব্যাকএন্ডের জন্য, `vsa`, `veda` বা `spark` দিয়ে `all` প্রতিস্থাপন করুন; সম্পূর্ণ এবং VDN এই কাস্টম CANN এক্সটেনশনগুলির প্রয়োজন নেই৷ সম্পাদনাযোগ্য চেকআউট উপলব্ধ রাখুন।

## চেকপয়েন্ট এবং অ্যালগরিদম পছন্দ

| পদ্ধতি | প্রয়োজনীয় মডেল সম্পদ | গণনা |
| --- | --- | --- |
| `full` | H3 বেস; LightX2V ডিফল্টভাবে 8-পদক্ষেপ, বা একটি সম্প্রদায় LoRA | ঘন মনোযোগ |
| `vsa` | সম্পূর্ণ অফিসিয়াল FastH3 V2 ছাত্র, সমস্ত 50টি প্রশিক্ষিত কম্প্রেশন গেট সহ | 8 ফরোয়ার্ড, 80% ভিডিও স্পারসিটি; লজিক্যাল KV64, নির্বাচিত KV ব্লকগুলি চিপে KV128 এর সাথে যুক্ত |
| `veda` | H3 বেস + LightX2V 8-পদক্ষেপ + অফিসিয়াল প্রশিক্ষিত Veda ভবিষ্যদ্বাণীকারী | মাথা পিছু গতিশীল Veda ব্লক রুট, নামমাত্র 90% স্পারসিটি |
| `vdn` | H3 বেস + অফিসিয়াল VDN স্টেজ-ডিএমডি চেকপয়েন্ট ডিরেক্টরি | স্থানীয় সফটম্যাক্স প্লাস 128-মাত্রিক শেখা ডেল্টানেট শাখা |
| `spark` | H3 বেস + LightX2V 8-ধাপ | Spark-H3 হায়ারার্কিক্যাল পার্টিশন এবং জয়েন্ট এক্স্যাক্ট/প্রক্সি সফটম্যাক্স, নামমাত্র 90% সঠিক-শাখা স্প্যার্সিটি |

তাদের আসল লাইসেন্সের অধীনে মডেলগুলি ডাউনলোড করুন। ওজন পুনরায় বিতরণ করা হয় না. বিভিন্ন পাতিত ছাত্রদের বিভিন্ন সময়সূচী এবং শেখা নিয়ম আছে; নির্বিচারে ওজনের উপর মনোযোগ অদলবদল করা মানসম্মত মানের গ্যারান্টি দেয় না। VSA এর জন্য অশূন্য প্রশিক্ষিত গেট প্রয়োজন। VDN এর শেখা শাখার ওজন প্রয়োজন। ডাউনলোড এবং প্রস্তুতির আদেশগুলি[মডেল সম্পদ](../docs/weights.md) এ রয়েছে।

সম্পূর্ণ, Veda এবং স্পার্ক ডিফল্টরূপে পিন করা **LightX2V আট-পদক্ষেপ LoRA** সক্ষম করে৷ মূল বহু-পদক্ষেপ মডেল চালানোর জন্য `--no-few-step-lora` ব্যবহার করুন৷ একটি প্রস্তুত সম্প্রদায় `--lora /models/style` লোডিং শেষ হওয়ার আগে LightX2V এর সাথে একত্রিত হয়; স্পষ্টভাবে অন্য সম্প্রদায়ের ছাত্র নির্বাচন করার সময় ডিফল্ট ছাত্র অক্ষম করুন। Veda সবসময় এর অফিসিয়াল প্রশিক্ষিত ভবিষ্যদ্বাণীর প্রয়োজন। VSA শুধুমাত্র সম্পূর্ণ অফিসিয়াল **FastH3 V2 সম্পূর্ণ চেকপয়েন্ট** গ্রহণ করে: আটটি ফরোয়ার্ড, 80% ভিডিও স্পারসিটি, ভিডিও/অডিও শিফট 10/3, টাইল64, নির্দেশিকা 1। এটি সরাসরি প্রকাশিত ওজন লোড করে এবং `--lora` নেয় না। VDN শুধুমাত্র তার সম্পূর্ণ অফিসিয়াল স্টেজ-DMD চেকপয়েন্ট গ্রহণ করে। উভয়ই একটি অতিরিক্ত সম্প্রদায় LoRA বা ছাত্র-অক্ষম পতাকা গ্রহণ করে না।

```bash
# Optional: provide the exact pinned LightX2V source locally instead of downloading.
h3-ascend serve --method full --model /models/MiniMax-H3 --devices 1 \
  --few-step-source /models/minimax_h3_fl2v_turbo_8step_v1.0_768p_bf16.safetensors
# Optional original 50-step model; the reporting baseline is Full eight-step.
h3-ascend serve --method full --model /models/MiniMax-H3 --devices 1 --no-few-step-lora
# General already-scaled Diffusers community LoRA, with no forced step schedule.
h3-ascend prepare-lora --source /models/style.safetensors --output /models/style
```

অফিসিয়াল PEFT উৎস একবার তার ঘোষিত আলফা/র্যাঙ্ক ব্যবহার করে স্বাভাবিক করা হয়; প্রস্তুত ফাইল হ্যাশ-চেক করা হয়. সমস্ত নির্বাচিত অ্যাডাপ্টার TP স্লাইসিং এবং INT8 কোয়ান্টাইজেশনের আগে একত্রিত হয়। কোন অনুরোধ-সময় LoRA ম্যাট্রিক্স গুণ নেই। সোর্স ফরম্যাট এবং নির্দিষ্ট সময়সূচীর জন্য[মডেল প্রস্তুতি](../docs/weights.md) দেখুন।

## একটি সার্ভার শুরু করুন

শুধুমাত্র এমন ডিভাইসগুলি ব্যবহার করুন যার অন্য কোন গণনা প্রক্রিয়া নেই। একটি কার্ডের জন্য:

```bash
export ASCEND_RT_VISIBLE_DEVICES=0
h3-ascend serve --method full --model /models/MiniMax-H3 \
  --precision int8 --devices 1 --offload text
```

অন্যান্য ব্যাকএন্ড একই সার্ভার API ব্যবহার করে:

```bash
h3-ascend serve --method vsa --model /models/FastH3-V2 \
  --precision int8 --devices 1 --offload text
h3-ascend serve --method veda --model /models/MiniMax-H3 \
  --predictor /models/veda/predictor.safetensors \
  --precision int8 --devices 1 --offload text
h3-ascend serve --method vdn --model /models/MiniMax-H3 \
  --lora /models/VDN/stage-dmd-step-250 --precision int8 --devices 1 --offload text
h3-ascend serve --method spark --model /models/MiniMax-H3 \
  --precision int8 --devices 1 --offload text
```

নির্বাচিত ডিভাইসগুলিতে একবারে একটি সার্ভার চালান। একটি মডেল লোড না করে জেনারেট করা নেটিভ vLLM-Omni কমান্ড পরিদর্শন করতে `--dry-run` যোগ করুন।

INT8 DiT রেসিডেন্ট রাখার সময় একক-কার্ডের উদাহরণ টেক্সট এনকোডার স্ট্রিম করে। নেটিভ রেসিপি DiT এর পরিমাপ করে; টেক্সট এনকোডার BF16 থেকে যায়, তাই এর মেমরি ফুটপ্রিন্ট এখনও লঞ্চ নীতিতে অন্তর্ভুক্ত করা প্রয়োজন। **BF16** এর জন্য, `--precision bf16` ব্যবহার করুন; প্রয়োজনে `--offload layer --no-precompute-adaln` স্পষ্টভাবে নির্বাচন করুন। INT8 নেটিভ রেসিপি ব্যবহার করে:

```json
{"transformer":{"method":"int8"}}
```

INT8 অনুমানগুলি BF16 Q/K/V মনোযোগ আকর্ষণ করে। মনোযোগ সঞ্চয়কারী, Veda পূর্বাভাস এবং VDN রাষ্ট্র তাদের নির্ধারিত নির্ভুলতা রাখে। এটি INT8 মডেলের অনুমান, এমন দাবি নয় যে প্রতিটি মনোযোগ অপারেশন INT8। নেটিভ রেসিপি BF16-এ অসমর্থিত স্তর বজায় রাখে। একক-কার্ড H3-এর একটি 96,768-ওয়াইড প্রজেকশন রয়েছে যা 65,535-এর NPU কোয়ান্টাইজড ম্যাটমুল আউটপুট সীমা অতিক্রম করেছে; TP তার প্রতি-র্যাঙ্কের প্রস্থকে পরিসরে কমাতে পারে।

**চার-কার্ড অনুমান** জন্য, নেটিভ টেনসর সমান্তরাল হেড শার্ডিং ব্যবহার করুন:

```bash
export ASCEND_RT_VISIBLE_DEVICES=0,1,2,3
h3-ascend serve --method spark --model /models/MiniMax-H3 \
  --precision int8 --devices 4 --parallel tp

# Eight cards: seven DiT attention heads per rank.
export ASCEND_RT_VISIBLE_DEVICES=0,1,2,3,4,5,6,7
h3-ascend serve --method full --model /models/MiniMax-H3 \
  --precision int8 --devices 8 --parallel tp
```

`--devices` 1, 2, 4, 7 এবং 8 সমর্থন করে, যা 56টি মাথাকে ভাগ করে। Veda শার্ডিংয়ের পরে বিশ্বব্যাপী ভবিষ্যদ্বাণীকারী প্রধান আইডিগুলি ধরে রাখে। সেভেন-কার্ড DiT TP একটি টেক্সট এনকোডার র‌্যাঙ্ক ব্যবহার করে কারণ এর 64 কোয়েরি / 8 KV হেড সাত দিয়ে ভাগ করা যায় না। `--offload none` (আবাসিক ওজন) ডিফল্ট চালু করে। মেমরি অপর্যাপ্ত হলে, `--offload text` ডিভাইসে DiT ধরে রাখার সময় শুধুমাত্র টেক্সট এনকোডার স্ট্রিম করে; `--offload module` সম্পূর্ণ উপাদান অদলবদল করে (পরীক্ষামূলক যোগ্যতা); `--offload layer` একটি সক্রিয় এবং একটি প্রিফেচড ব্লক রেখে উভয় উপাদান স্ট্রীম করে। নীচের সম্পূর্ণ মিলিত-অফলোড রেফারেন্সটি উভয় হার্ডওয়্যার প্ল্যাটফর্মে স্পষ্টভাবে `--offload layer` (`omni-layer-prefetch1-vae-resident-v1`) ব্যবহার করে। নতুন এন্ড-টু-এন্ড পরিমাপ **INT8 শুধুমাত্র** ব্যবহার করে, আবাসিক নির্বাহ থেকে শুরু করে এবং প্রতিটি প্রয়োজনীয় অফলোড ফলব্যাক চিহ্নিত করে। বিচ্ছিন্ন মনোযোগ এবং DiT-ব্লক তুলনা উভয় ডিভাইসেই BF16 ব্যবহার করে: স্তর 0/24/49, তিনটি রান প্রতিটি, নয়টি সময় যোগ করে এবং নয়টি দিয়ে ভাগ করে। ঐচ্ছিক `--parallel ulysses` নন-VDN পাথগুলির জন্য উন্মুক্ত করা হয়েছে; TP ডিফল্ট রয়ে গেছে। নেটিভ টাইলযুক্ত VAE ডিকোডিং এখন সমস্ত নির্বাচিত কার্ডে ডিফল্ট (`--vae-parallel-size 0`); একটি একক ডিকোডার র‍্যাঙ্কের জন্য `--vae-parallel-size 1` ব্যবহার করুন। INT8 ফুল / 124-ফ্রেম পাইপলাইনটি এক, দুই, চার এবং আটটি VAE র‌্যাঙ্ক সহ পাস করেছে। অন্যান্য পদ্ধতি/ফ্রেম-গণনা সমন্বয় E2E ম্যাট্রিক্সে থাকে।

আবাসিক NPU লঞ্চ সার্ভার প্রস্তুতির আগে AdaLN ফলাফল প্রস্তুত করে। প্রস্তুতি লোড করা মডেলের সমাধান করে এবং LoRA এর প্রকৃত সিগমা অবস্থান, DiT আপডেট গণনা এবং ভিডিও/অডিও স্থানান্তরগুলি একত্রিত করে; এটি আটটি ধাপে হার্ড কোডেড নয়। একজন শিক্ষক/কাস্টম-ছাত্র লঞ্চ নির্দিষ্ট করতে `serve --steps N` ব্যবহার করুন এবং `generate --steps N`-এ একই গণনা ব্যবহার করুন। একটি বিরোধপূর্ণ পাতিত চেকপয়েন্ট সময়সূচী প্রত্যাখ্যান করা হয়েছে। প্রয়োজনীয় পরিকল্পনার সাথে ক্যাশের ক্ষমতা বৃদ্ধি পায়। মূল অভিক্ষেপ গণিত রাখা হয়; AdaLN মাস্টার ওয়েট CPU-তে থাকে, যখন প্রস্তুত ফলাফল NPU-তে থাকে। TP4/TP8 সঠিক টাইমস্টেপ ইনপুটগুলি থেকে নেটিভ টাইম এম্বেডিংগুলিকেও স্মরণ করে যাতে নিম্ন-বিট FP32 হ্রাসের বৈচিত্র্য ডাউনস্ট্রিম ক্যাশেগুলিকে অবৈধ করে না। ওজন, সংখ্যাসূচক সেটিংস এবং সর্ব-র্যাঙ্ক হিট চুক্তি এখনও পুনঃব্যবহার রক্ষা করে। একটি ভিন্ন সময়সূচী প্রি-কম্পিউট করতে নতুন কনফিগারেশন দিয়ে পুনরায় আরম্ভ করুন; একটি অপ্রস্তুত ইনপুট মূল গণনা ব্যবহার করে এবং ওজন স্থানান্তর করতে পারে। `--no-precompute-adaln` প্রস্তুতি অক্ষম করে; DiT মডিউল/লেয়ার স্ট্রিমিং এটিকে ডিফল্টরূপে অক্ষম রাখে।

একক-কার্ড 345-ফ্রেম Spark/VSA/VDN, আসল বৈধ অপারেটরগুলির সাথে `--offload layer --no-precompute-adaln` ব্যবহার করুন৷ E2E টেবিল এই নেটিভ লেয়ার অফলোড সেলগুলিকে †L দিয়ে চিহ্নিত করে; ‡R পূর্ববর্তী রান থেকে পুনরায় ব্যবহার করা মিলে যাওয়া পরিমাপ সনাক্ত করে। অন্যান্য সমস্ত কক্ষ তাদের পৃথকভাবে নথিভুক্ত রেসিডেন্সি নীতি বজায় রাখে।

লঞ্চার স্থানীয় কর্মীদের অনুরোধের সময়সীমা 7200 সেকেন্ডে সেট করে যাতে একটি দীর্ঘ ভিডিও আপস্ট্রিম 600-সেকেন্ড ডিফল্ট দ্বারা বাতিল না হয়। এই সীমা ওভাররাইড করতে লঞ্চের আগে `VLLM_OMNI_DLO_DP_WAVE_TIMEOUT` সেট করুন; এটি অপেক্ষার আচরণ পরিবর্তন করে, মডেল গণনা বা মাপা অনুরোধের সময়কাল নয়।

## দুটি 768p কেস তৈরি করুন

একটি UTF-8 প্রম্পট ফাইল তৈরি করুন, একটি সার্ভার শুরু করুন, তারপরে এর মিলে যাওয়া ধাপ সংখ্যা ব্যবহার করুন:

```bash
printf '%s\n' 'A cyclist rides through a green park, cinematic tracking shot.' > prompt.txt
for CASE in 1344-124 1344-345; do
  h3-ascend generate --case "$CASE" --prompt-file prompt.txt \
    --method full --seed 7 --output "outputs/${CASE}.mp4"
done
```

ক্লায়েন্টের কাছে সার্ভারের `--method` পাস করুন: সমস্ত পাঁচটি পদ্ধতি (Full/VSA/Veda/VDN/Spark) আটটি প্রকৃত ফরোয়ার্ডে ডিফল্ট। ঐচ্ছিক মূল বহু-পদক্ষেপ মডেলের জন্য, সার্ভারের সাথে মিলে যাওয়া `generate --method full --no-few-step-lora` (50 ধাপ) ব্যবহার করুন। একটি স্পষ্ট `--steps` একটি পৃথকভাবে প্রস্তুত কমিউনিটি ছাত্রদের জন্য উপলব্ধ থাকে। `--guidance-scale` ঐচ্ছিক; বাদ দেওয়া দেশীয় নীতি সংরক্ষণ করে। কোন পরিমার্জিত পর্যায় যোগ করা হয় না. ক্লায়েন্ট MP4 এবং একটি JSON টাইমিং রসিদ সংরক্ষণ করে।

1344×768, টেক্সট এনকোডিং, ভিডিও/অডিও ডিকোডিং এবং MP4 লেখা সহ আটটি প্রকৃত DiT আপডেট। লোড হচ্ছে, পূর্বে LoRA মার্জ, AdaLN প্রস্তুতি এবং ওয়ার্মআপগুলি বাদ দেওয়া হয়েছে৷ আবাসিক DiT পছন্দ করুন; আবাসিক সারিগুলি আনুষ্ঠানিক অনুরোধের আশেপাশে প্রতিটি র‌্যাঙ্কে শূন্য AdaLN মিস এবং ওজন স্থানান্তর যাচাই করে। রেকর্ড করা OOM-এর পরে, চিহ্নিত একক-কার্ড 345-ফ্রেম সেলগুলি নেটিভ লেয়ার অফলোড ব্যবহার করে এবং মেলে পুনঃব্যবহার করে, অনুরোধ অনুযায়ী পূর্বের পরিমাপ সম্পূর্ণরূপে যাচাই করা হয়; এই কোষগুলিকে তাজা পরিমাপ হিসাবে উপস্থাপিত করার পরিবর্তে স্পষ্টভাবে চিহ্নিত করা হয়েছে।

## গুণগত ফলাফল এবং বৈধতা

Ascend 910B3 শুধুমাত্র: **1344×768, 345 নেটিভ ফ্রেম, 24 FPS (14.375 সেকেন্ড, প্রায় 14.4 সেকেন্ড)**, অডিও সহ।

সমস্ত পাঁচটি পদ্ধতি আটটি ফরোয়ার্ড ব্যবহার করে। বাম: BF16। ডানদিকে: নেটিভ W8A8 INT8। সমস্ত নমুনা একটি কার্ড, একই প্রম্পট, সাধারণ বীজ **7** এবং মিলিত অফলোড ব্যবহার করে।

> একটি সাইকেল আরোহী একটি শান্ত সবুজ পার্কের পথ, মসৃণ সিনেম্যাটিক ট্র্যাকিং শট, প্রাকৃতিক দিনের আলোতে রাইড করে।
